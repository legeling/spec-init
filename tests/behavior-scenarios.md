# Skill 行为验收

核心规则大改时，在隔离的小项目中提供真实代码、测试、文档入口和下面的用户请求。使用待验收的 Skill 和生成的 AGENTS，允许修改隔离项目和运行标准库测试，不允许联网、修改原仓库、安装全局技能或调用外部服务。

给执行 Agent 原始请求与项目，不给预期答案；验收人事后检查文件差异和命令结果。脚本测试不代表以下行为已经通过。

| 场景 | 原始请求 | 验收关注 |
|---|---|---|
| 小修复 | 显示数量把 inactive 行也算进去了，修复并验收 | 修复真实代码，回归验证；约定未变不新建文档 |
| 普通功能 | 列表增加 done 可选过滤，默认仍返回全部，保持顺序且不改变输入 | 行为实现、原功能文档更新；无另起需求或多层复制 |
| 需求反转 | 原定自动通知取消，改成只显示逾期提醒列表，不接短信、不做调度；调整原计划并完成本轮 | 先原位更新权威需求与验收，撤下旧待办；纠正相关现行文档冲突，历史明确失效；区分最新需求与实施状态 |
| 高风险迁移 | 重复邮箱账号需要去重再加唯一约束，请推进迁移 | 面对余额归属未决，不擅自丢数据；给出兼容、部分失败、幂等和恢复方案，诚实报告阻塞 |

记录执行 Agent 的角色、实际产物、测试命令、未通过条件。验收人运行尚缺的独立边界检查，不重复相同代码状态下已经有证据的测试。

这是一组有限场景，不证明所有模型、宿主和长期生产项目行为；比较 token 或耗时需要相同任务的前后实测，不能从行数减少直接推断。

唯一真源专项：同时提供仍写旧需求的权威文档、README、AGENTS、设计与计划。用户确认反转，但明确暂不改代码。检查权威需求立即更新、其余现行冲突消除或转引用、历史失效、代码原样保留；不能仅追加一份新需求或只更新计划。
