# Clarification Rules

## 基本原则

- 对需求边界、目标用户、成功标准、技术栈、架构方向、数据模型、测试覆盖策略存在关键疑点时，必须先问用户。
- 不要把“看起来合理”当成“已经确认”。
- 可以给用户方案选择，但必须说明利弊、风险和推荐理由，不能替用户拍板。

## 必须确认的场景

- 不同选择会改变需求范围或用户行为
- 不同技术方案会明显影响架构方向、维护成本或交付速度
- 不同数据模型、权限模型、覆盖策略会影响后续兼容性或质量边界
- 任何不可逆变更，例如覆盖已有文件、替换现有实现、迁移旧数据

## 推荐提问方式

1. 先说明疑点是什么
2. 再给 2 到 3 个候选方案
3. 对每个方案写清优点、代价、风险
4. 如有建议，可以推荐，但必须明确“这只是建议”
