# Coding Standards

## 基本原则

- 先需求、再设计、再实现，禁止跳过文档直接大规模编码。
- 优先做最小正确改动，避免引入不必要的抽象。
- 不确定的信息写入文档的 `[待确认]`，不要在代码里靠猜测补齐。

## 代码变更要求

- 新功能必须能回链到 `FR-*`、`DES-*`、`TEST-*`、`T-*`。
- 接口、数据结构或配置项变化时，必须同步更新 `docs/02-design/README.md`。
- 关键技术权衡应记录到 `docs/adr/`。

## 禁止行为

- 用硬编码假数据掩盖真实问题
- 用注释掉出错代码的方式“修复”问题
- 用 `TODO` 占位代替关键逻辑
- 用默认值吞掉本应暴露的缺失字段或异常
