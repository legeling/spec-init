# Implementation Plan: Demo App

> 更新时间：2026-04-29
>
> 这份文档安排交付顺序，不替代设计文档。

## 1. 实施目标

先交付一套可直接使用的初始化骨架和文档模板，再补足示例与追踪关系，确保新用户可以立即理解如何开始项目。

## 2. 里程碑

| Milestone | 目标 | 输入 | 输出 | 验收方式 |
|---|---|---|---|---|
| `M1` | 生成项目骨架与核心文档模板 | 项目名称、项目类型 | README、AGENTS、docs、src、tests、scripts | 所有基础文件一次生成成功 |
| `M2` | 补齐追踪关系与示例内容 | `M1` | `FR`/`DES`/`TEST`/`T` 完整链路、示例文档 | 至少一条链路可直接展示 |

## 3. 建议顺序

1. 先生成目录和基础文件
2. 再完善 requirements、design、tdd、tasks 的追踪关系
3. 最后检查 README 和 AGENTS 是否与项目结构一致

## 4. 依赖关系

| 项目 | 依赖 | 说明 |
|---|---|---|
| 文档模板输出 | 初始化脚本 | 没有骨架就没有后续文档 |
| 追踪链建立 | requirements + design + tdd | 必须先有文档 ID 才能回链到任务 |

## 5. 高风险优先项

- 先验证模板是否足够清楚，避免生成后用户仍然不会写
- 先验证脚本是否能稳定替换项目名、类型和日期

## 6. 文档与测试同步计划

- 当模板结构变化时，同步更新 `docs/02-design.md` 中的承接说明
- 当新增高优需求时，先补 `docs/04-tdd-plan.md` 的映射，再扩展任务清单
- 当目录结构变化时，同步更新 `README.md` 和 `AGENTS.md`

## 7. 发布 / 回滚思路

- 发布方式：先内部试用，再公开发布
- 回滚思路：保留旧模板版本，若新模板误导用户则回退到上一版

## 8. 追踪落地计划

- `M1`: 先落 `FR-001 -> DES-001 -> TEST-001 -> T-001`
- `M2`: 再补 `FR-002` 和 `FR-003` 的设计、测试和任务链路
- 第二版再考虑项目类型定制化

## 9. 实施计划自检

- 这里安排的是交付顺序，不是重新做设计
- 高风险和高不确定性被前置验证
- 每个里程碑都有可观察的验收产出
- 文档更新和测试补齐已经被纳入计划

## 10. 阻塞项与待确认

- 是否需要补充针对 `cli` / `api` 的专项示例
- 是否要给脚本增加对更多模板变量的支持
